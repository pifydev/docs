# Adaptive Favicon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the selected transparent, light/dark-adaptive Pify favicon on every English and Vietnamese documentation route.

**Architecture:** Use the Next.js App Router `app/icon.svg` file convention as the single metadata source, while retaining `public/favicon.svg` as a stable compatibility URL. Remove the manual nested-layout icon declaration to avoid duplicate `<link rel="icon">` tags, and verify the generated metadata plus both SVG endpoints with Playwright.

**Tech Stack:** Next.js 16 App Router metadata files, SVG/CSS `prefers-color-scheme`, Playwright, Vitest, TypeScript

**Files:**

- Modify: `tests/e2e/docs.spec.ts`

- [ ] **Step 1: Write the failing browser test**

Add this test after `publishes one page title and paired canonical metadata`:

```ts
test("publishes one adaptive Pify favicon for both locales", async ({
  page,
  request,
}) => {
  let iconHref = "";

  for (const path of ["/en/quickstart", "/vi/quickstart"]) {
    await page.goto(path);

    const icons = page.locator('link[rel="icon"]');
    await expect(icons).toHaveCount(1);
    await expect(icons).toHaveAttribute("type", "image/svg+xml");
    await expect(icons).toHaveAttribute("sizes", "any");

    iconHref = (await icons.getAttribute("href")) ?? "";
    const iconUrl = new URL(iconHref, "http://127.0.0.1:3010");
    expect(iconUrl.pathname).toBe("/icon.svg");
    expect(iconUrl.search).not.toBe("");
  }

  const [metadataIcon, compatibilityIcon] = await Promise.all([
    request.get(iconHref),
    request.get("/favicon.svg"),
  ]);

  for (const response of [metadataIcon, compatibilityIcon]) {
    expect(response.ok()).toBe(true);
    expect(response.headers()["content-type"]).toContain("image/svg+xml");
  }

  const svg = await metadataIcon.text();
  expect(svg).toContain("@media (prefers-color-scheme: dark)");
  expect(svg).toContain(".mark { fill: #09090b; }");
  expect(svg).toContain(".mark { fill: #ffffff; }");
});
```

- [ ] **Step 2: Remove the duplicate manual icon metadata**

In `app/[lang]/layout.tsx`, remove only this property from the exported metadata object:

```ts

```

Keep `metadataBase`, title, and description unchanged. Next.js will generate the icon link from `app/icon.svg`, as documented by the official [favicon, icon, and apple-icon convention](https://nextjs.org/docs/app/api-reference/file-conventions/metadata/app-icons).

In `proxy.ts`, add `favicon.svg` and `icon.svg` to the negative matcher alongside `favicon.ico`. This keeps the Fumadocs locale middleware from rewriting static favicon requests to localized documentation routes.
