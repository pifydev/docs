## Review method

Post-tag `main` was not used as release evidence.

Each manifest pair was checked in manifest order for English/Vietnamese factual parity, heading and artifact structure, code equality where required, metadata, official references, and exact identifiers. A `substantive` row changes a released behavior or interface explanation; `release-pin` changes the release/date/source boundary or related inventory wording without changing that page's Pi runtime contract; `verified-unchanged` means the pair required no edit after source-diff review. Rendering remains `pending` because no browser UI review has been performed.

## Removal and replacement audit

The migration replaced the following material claims in both locales. These are not treated as mechanical pin changes:

| Obsolete claim                                                                                                                                                         | Pi 0.85.0 replacement                                                                                                                                                                                                                                                                                                                                               | Exact pinned evidence                                                                              |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| The experimental remote boundary was centered on `PiServer` accepting a `PiServerService`, adapting Pi AI DTOs, and bridging one server package to the protocol.       | The optional experimental boundary is split across transport-neutral `Client`, strict routed `pi-protocol` envelopes and framing, Chord-owned service semantics, and server- or Session-scoped presentation attachments. Live routes retain exact `{ serverId, sessionId, attachmentId }` identities, while Session and Agent Harness objects remain process-local. | [client README][client-readme], [protocol README][protocol-readme], [server README][server-readme] |
| After a completed Turn, `prepareNextTurn` ran before `shouldStopAfterTurn`, followed by one steering poll.                                                             | `shouldStopAfterTurn` sees the completed-Turn snapshot first; steering is polled next; `prepareNextTurn` runs only when another inner Turn is already required; and an initially empty steering queue is refreshed after preparation.                                                                                                                               | [Agent Loop source][agent-loop]                                                                    |
| The built-in `write` success result could describe JavaScript string length as a byte count.                                                                           | The success result reports only `Successfully wrote to <path>`; callers needing encoded byte size must measure that encoding themselves.                                                                                                                                                                                                                            | [`write` Tool source][write-source]                                                                |
| The `AgentSessionEvent` declaration contained two identical `auto_retry_end` union arms.                                                                               | The duplicate declaration is gone; the reviewed inventory no longer needs to deduplicate the source union.                                                                                                                                                                                                                                                          | [`AgentSession` source][agent-session]                                                             |
| Automatic compaction checks occurred only after `agent_end` and before a later prompt, leaving the mid-run behavior effectively unreleased in the documented baseline. | Tool results are appended before a new mid-run threshold check and optional compaction ahead of the next assistant response; the post-run and pre-prompt checks remain. A terminating Tool batch without queued continuation skips the unnecessary mid-run check.                                                                                                   | [`AgentSession` source][agent-session]                                                             |
| Branch summaries used a fixed 2,048-token response cap.                                                                                                                | The cap is 4,096 tokens, still bounded by a smaller positive `model.maxTokens`, and summaries ending with `stopReason: "length"` are rejected as incomplete.                                                                                                                                                                                                        | [branch summarization source][branch-summarization]                                                |
| Built-in summary generation disabled Tool calls by forcing `toolChoice: "none"`.                                                                                       | The summarization request supplies no Tool definitions and does not force a `toolChoice` field.                                                                                                                                                                                                                                                                     | [compaction source][compaction-source]                                                             |
| `SessionManager.inMemory(cwd?, options?)` only described a new fileless tree, and the surrounding guide implied every `SessionManager` owns a Pi session file.         | `SessionManager.inMemory(cwd?, options?, entries?)` can restore an application-owned `FileEntry[]`; the host owns validation and durable synchronization, and Pi creates no session file for that manager.                                                                                                                                                          | [`SessionManager` source][session-manager]                                                         |

No reviewed topic was removed without a source-backed replacement. Consequently, no preservation allowance was required, `content/preservation-manifest.json` is unchanged, and no preservation floor was lowered.
