# Pi 0.99.2 bilingual audit

## Scope and method

This audit covers the 46 public English/Vietnamese pairs in `content/translation-manifest.json` for the Pi `v0.99.2` publication baseline. Source authority is the published release chain (`v0.99.0`, `v0.99.1`, and `v0.99.2`) and the exact reviewed commit [`005af57d88ee23b33778f343a9595b32e67ff788`](https://github.com/earendil-works/pi/commit/005af57d88ee23b33778f343a9595b32e67ff788); published package declarations are used only where they define the documented public surface.

### Authority hierarchy

1. **Published GitHub releases v0.99.2, v0.99.1, v0.99.0** establish published release chronology.
2. **Exact source at commit 005af57d88ee23b33778f343a9595b32e67ff788 in read-only D:\pi** establishes the release-pinned implementation.
3. **Published npm metadata and declarations for 0.99.2** establish the published package surface.
4. **Official Markdown docs contained in tag v0.99.2** establish tagged documentation details.
5. **https://pi.dev/docs/latest only as secondary topic organization/reader-explanation guidance** may help readers navigate, but is not release authority.

Release tag/commit/npm metadata/public declarations must agree before describing an API as published. Latest and post-tag main can suggest inspection topics but cannot establish 0.99.2 behavior.

For every pair, the audit read both files and compared frontmatter, heading hierarchy, callouts, tables, internal links, pinned upstream links, technical relationships, and code-fence language/count. Identifiers, commands, flags, events, package names, types, and established IT terms remain English; Vietnamese prose states the same boundary without broadening or weakening it. A deletion is permitted only for source-proven false material or an exact same-page duplicate. All other rows retain `none`.

`substantive` means technical, prose, or structural content changed during the 0.99.x work; `pin-only` means only metadata, date, version, or source authority changed; `verified unchanged` means the full pair was read and needed no change. The classifications were made by comparing each EN/VI pair with pre-refresh `6d2c9e5`, then manually checking every non-pin diff. The fence column is measured from the current files, not copied from a plan.
